# Build toolchains and declared deployment suppliers

Status: proposed for source integration. This decision is effective only when the accompanying HouseArchitectureNorms refinement and the affected producer/consumer source are reviewed and accepted together. It does not assert that the full native build or deployed closure has been received.

## Governing requirements

The [existing architecture norms](../../../../data/records/house-architecture-norms.json) prohibit third-party imports by default, require substantive house capability ownership, plain Node source and honest dependency declarations. The [LAGOON production amendment](https://github.com/red-cup-engineering/computer-engineering-services-section/blob/b11c409892d03007e314b68adf092c45d1720080/services/computer-systems-engineering-services-section/services/computer-operating-system-services-section/apps/computer-deployment-engine/content/text/documents/articles/notes/2026/08/29/2026-08-29-lagoon-architecture.md) requires one recorded recursive source hierarchy, necessary source generation, the authoritative whole workspace lock, registry.561.group package supply, and ordinary Guix realization. Neither a previously merged external import nor registry availability by itself waives a norm.

Two explicit distinctions are required: a source compiler is a build supplier rather than application logic; and a package selected by an actual host/profile declaration is a genuine runtime dependency even when the application loader performs its import from configuration.

## Decision: bounded compiler stage

The runtime default remains Node builtins, relative imports and house-owned capabilities. A pinned external compiler may be selected only by a reviewed capability-specific source decision that identifies its actual installed artifact and confines invocation to a declared build stage. The stage must consume authenticated authored inputs and emit the owning package's declared ABI, bytecode or data products. The compiler must not be part of that consumer's deployed executable dependency closure. A devDependency label alone is insufficient evidence: inspect the real production pack and its reached entrances. A generator source file retained in the package is not a runtime entrance merely because it is published; no export, bin, declared application or reached import may make its build-only compiler invocation reachable at runtime.

This increment admits only the Ethereum Articulating compilation stage described below. Other compilers or capabilities need their own reviewed source decision; existing TypeScript/esbuild uses are not blanket authorization. The plain-Node norm remains unchanged. Existing TypeScript emission may be qualified only as an explicitly bounded migration prerequisite for already-authored consumers, not a reason to author more TypeScript or preserve an obsolete codec indefinitely.

The owning Ethereum producer is preferable to a new house implementation of the Solidity compiler: the latter would require maintaining Solidity language semantics, optimizer behavior, EVM code generation and compiler conformance, while the required house capability is producing the exact four authored contracts' ABI and bytecode. Reusing the existing unreceived generic Solidity wrapper would add a second producer without a receiving consumer. The Ethereum owner already defines the source set, optimizer/EVM settings, output names and semantic consumption; the selected compiler performs only the bounded language translation.

## Decision: declared host/profile dependencies are used

For an explicitly identified deployment-root package, a dependency is used when an exact selected host, instance, profile or machine declaration names a real public entrance that the native loader admits for that role. Retain the declaration's repository, revision, path and module/subpath in receiving evidence. Traverse nested declaration modules, including obligation drivers and schedules, according to the actual loader. Verify that the target package and exported entrance exist, that the intended role activates it, and that the production pack supplies its real transitive closure. Do not add dummy imports to satisfy a syntactic audit or remove original declarations merely to obtain a green build. An ordinary library's unused dependency is not excused by this deployment-root rule.
