# 2026-06-16

## Package Bin Manifest Consolidation

Today I moved the standard `package.json#bin` projection into
`@emsenn/jsnode/workspace` as `packageBinManifest(manifest, packageName)`.

The immediate pressure came from AGRODAO: the host was reading
`lib/jsnode/package.json` itself and carrying a local parser just to mount the
`@emsenn/jsnode` bins through `@emsenn/web`'s package-bin transport. That was the
wrong ownership. AGRODAO should compose transports; it should not reinterpret
Node package metadata when `jsnode` already owns workspace package discovery and
manifest facts.

The new helper is pure over an already-parsed manifest. It keeps the standard
Node behavior:

- string-valued `bin` is named by the package;
- object-valued `bin` keeps declared command names;
- non-string targets are ignored;
- object-valued bins are sorted for stable discovery output.

`discoverWorkspace()` now uses the same projection to derive
`JSNodePackage.manifest.bins`, so the carrier fact path and the web transport
path agree on what a package bin is. This is still a projection of manifest
facts into carriers; it is not a new AGRODAO data model.

## Rename To Computing-JSNode

The package boundary now matches the conceptual ownership: `lib/jsnode` moved to
`lib/computing-jsnode`, and the package name is `@emsenn/computing-jsnode`.

I also moved the package-bin carrier vocabulary out of `@emsenn/web/server`.
`web` still owns HTTP execution, OpenAPI, HTML negotiation, request body limits,
and child-process plumbing. The Node package facts now live in
`@emsenn/computing-jsnode/package-bin`:

- `PackageBinCarrier`;
- `packageBins()`;
- `packageBinDiscovery()`;
- `packageBinEndpoint()`;
- the EAVT media-type convention.

That collapses the duplicate `web.package-bin.*` ontology into the same package
that already owns workspace packages, manifest facts, package topology, and the
`package.json#bin` projection.

The dependency direction is now:

relating carriers -> computing -> computing-jsnode package/bin carriers -> web
HTTP transport -> AGRODAO mount.

AGRODAO now looks up `@emsenn/computing-jsnode` in the workspace and serves its
declared `bin` scripts at `/jsnode-bins/`.

## Web Transport Decoupling

I corrected the dependency direction again: `@emsenn/web` should not know what a
package bin is.

`@emsenn/computing-jsnode/package-bin` still owns the package-bin carrier
semantics:

- package manifest admission;
- executable path resolution;
- package-bin utterance facts;
- `packageBins()` and `packageBinFact()`.

`@emsenn/web/server` now exposes a generic stdin/stdout EAVT process transport
instead. AGRODAO adapts computing-jsnode package-bin carriers into generic web
process descriptors at the mount point. The dependency direction is now:

computing-jsnode package-bin carriers -> AGRODAO adapter -> web stdio/EAVT
transport.

There is no `@emsenn/web -> @emsenn/computing-jsnode` dependency anymore.
