# 2026-06-16

## Package Bin Manifest Consolidation

Today I moved the standard `package.json#bin` projection into `@emsenn/jsnode/workspace` as `packageBinManifest(manifest, packageName)`.

The immediate pressure came from 561 Group Operations Manifold: the host was reading `lib/jsnode/package.json` itself and carrying a local parser just to mount the `@emsenn/jsnode` bins through `@emsenn/web`'s package-bin transport.
That was the wrong ownership.
561 Group Operations Manifold should compose transports; it should not reinterpret Node package metadata when `jsnode` already owns workspace package discovery and manifest facts.

The new helper is pure over an already-parsed manifest.
It keeps the standard Node behavior:

- string-valued `bin` is named by the package;
- object-valued `bin` keeps declared command names;
- non-string targets are ignored;
- object-valued bins are sorted for stable discovery output.

`discoverWorkspace()` now uses the same projection to derive `JSNodePackage.manifest.bins`, so the carrier fact path and the web transport path agree on what a package bin is.
This is still a projection of manifest facts into carriers; it is not a new 561 Group Operations Manifold data model.

## Rename To Computing-JSNode

The package boundary now matches the conceptual ownership: `lib/jsnode` moved to `lib/computing-with-jsnode`, and the package name is `@emsenn/computing-with-jsnode`.

I also moved the package-bin carrier vocabulary out of `@emsenn/web/server`.
`web` still owns HTTP execution, OpenAPI, HTML negotiation, request body limits, and child-process plumbing.
The Node package facts now live in `@emsenn/computing-with-jsnode/package-bin`:

- `PackageBinCarrier`;
- `packageBins()`;
- `packageBinDiscovery()`;
- `packageBinEndpoint()`;
- the EAVT media-type convention.

That collapses the duplicate `web.package-bin.*` ontology into the same package that already owns workspace packages, manifest facts, package topology, and the `package.json#bin` projection.

The dependency direction is now:

relating carriers -> computing -> computing-with-jsnode package/bin carriers -> web HTTP transport -> 561 Group Operations Manifold mount.

561 Group Operations Manifold now looks up `@emsenn/computing-with-jsnode` in the workspace and serves its declared `bin` scripts at `/jsnode-bins/`.

## Web Transport Decoupling

I corrected the dependency direction again: `@emsenn/web` should not know what a package bin is.

`@emsenn/computing-with-jsnode/package-bin` still owns the package-bin carrier semantics:

- package manifest admission;
- executable path resolution;
- package-bin utterance facts;
- `packageBins()` and `packageBinFact()`.

`@emsenn/web/server` now exposes a generic stdin/stdout EAVT process transport instead.
561 Group Operations Manifold adapts computing-with-jsnode package-bin carriers into generic web process descriptors at the mount point.
The dependency direction is now:

computing-with-jsnode package-bin carriers -> 561 Group Operations Manifold adapter -> web stdio/EAVT transport.

There is no `@emsenn/web -> @emsenn/computing-with-jsnode` dependency anymore.
