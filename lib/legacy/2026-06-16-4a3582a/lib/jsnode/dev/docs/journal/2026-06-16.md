# 2026-06-16

## Package Bin Manifest Consolidation

Today I moved the standard `package.json#bin` projection into
`@emsenn/jsnode/workspace` as `packageBinManifest(manifest, packageName)`.

The immediate pressure came from AGRODAO: the host was reading
`lib/jsnode/package.json` itself and carrying a local parser just to mount the
`@emsenn/jsnode` bins through `@emsenn/web`'s package-bin transport. That was the
wrong ownership. AGRODAO should compose transports; it should not reinterpret
Node package metadata when `jsnode` already owns workspace package discovery and
manifest facts.

The new helper is pure over an already-parsed manifest. It keeps the standard
Node behavior:

- string-valued `bin` is named by the package;
- object-valued `bin` keeps declared command names;
- non-string targets are ignored;
- object-valued bins are sorted for stable discovery output.

`discoverWorkspace()` now uses the same projection to derive
`JSNodePackage.manifest.bins`, so the carrier fact path and the web transport
path agree on what a package bin is. This is still a projection of manifest
facts into carriers; it is not a new AGRODAO data model.

## Route Cleanup Follow-Up

The AGRODAO side now consumes `packageBinManifest()` rather than carrying its
own `package.json#bin` parser. That keeps the route contraction grounded in the
jsnode package carrier path:

manifest facts -> `packageBinManifest()` -> web package-bin transport ->
AGRODAO `/jsnode-bins`.
